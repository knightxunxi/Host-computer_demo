# M8 后续开发路线

## 1. 当前基线

M8 后项目已经具备第一版可运行能力：Qt Widgets 主界面、内置 Modbus TCP 模拟器、主监控、报警记录、操作日志、配方、趋势曲线、CSV 导出、烟测脚本和打包脚本。

后续路线不再只做“能跑”，而是逐步补齐企业项目里更接近真实交付的部分：权限、批次、配方版本、报警闭环、模拟器独立化、通信诊断、自动化测试和部署发布。

## 2. 推荐推进顺序

| 阶段 | 目标 | 先做内容 | 暂不做内容 |
| --- | --- | --- | --- |
| M9 用户与权限 | 让系统知道是谁在操作 | 用户表、默认用户、切换用户、角色权限、真实操作日志 | 密码复杂度、账号锁定、审计报表 |
| M10 批次管理 | 让生产数据可以按批次追溯 | 批次号、计划数量、开始/结束、批次统计 | 与 MES/ERP 对接 |
| M11 配方增强 | 让配方更接近生产使用 | 多配方、复制、版本、下发记录 | 电子签名、审批流程 |
| M12 报警增强 | 让报警从“记录”变成“处理闭环” | 查询筛选、处理建议、确认人、恢复状态 | 大屏统计、短信/邮件通知 |
| M13 模拟器增强 | 让无硬件学习覆盖更多异常 | 传感器点位、执行机构状态、故障注入、质量波动 | 复杂物理仿真 |
| M14 模拟器拆分 | 建立真实协议边界 | 模拟器独立进程、上位机通过协议连接 | 多设备部署 |
| M15 通信健壮性 | 接近现场通信要求 | 超时、重连、质量标识、诊断页 | 多 PLC 冗余 |
| M16 测试增强 | 降低后续改动风险 | 单元测试、数据库测试、协议烟测 | 完整 CI/CD |
| M17 部署增强 | 接近可交付安装包 | 配置、日志目录、版本号、安装包说明 | 自动升级 |
| M18 协议扩展 | 扩展真实设备接入能力 | Modbus RTU、Snap7/S7、OPC UA 选一个 | 同时支持全部协议 |

## 3. M9 细化任务

M9 先完成学习版用户权限闭环：

1. 数据库增加 `users` 表，保存登录名、中文显示名、角色、启用状态、密码哈希和最后登录时间。
2. 初始化三个默认用户：操作员、工程师、管理员。
3. 状态栏显示当前用户，并提供“切换用户”入口。
4. 操作日志从固定“系统”改为记录当前登录用户。
5. 配方保存和下发先限制为工程师或管理员，普通操作员只保留监控和基础操作权限。
6. 为了不影响自动化烟测，程序启动时先自动登录默认操作员，后续再根据需要改成强制登录。

## 4. 默认账号

| 角色 | 登录名 | 显示名 | 初始密码 | 说明 |
| --- | --- | --- | --- | --- |
| 操作员 | `op001` | 张三 | `123456` | 默认自动登录，适合监控和基础操作 |
| 工程师 | `eng001` | 李工 | `123456` | 可调整和下发配方 |
| 管理员 | `admin` | 管理员 | `admin123` | 预留系统管理权限 |

这些账号只用于学习项目。真实项目应增加密码复杂度、密码修改、禁用账号、登录失败锁定和权限配置界面。

## 5. M10 细化任务

M10 先完成学习版批次追溯闭环：

1. 数据库增加 `batches` 表，保存批次号、配方、操作员、计划数量、开始时间、结束时间、产量和状态。
2. 新增“批次管理”页面，支持生成批次号、开始批次、结束批次和查看最近批次。
3. 开始批次时记录当前用户、当前配方和当前生产计数基线。
4. 结束批次时要求先停止产线，再把当前批次数量、良品、不良和良率写入数据库。
5. 将批次开始/结束命令下发给模拟 PLC，模拟器收到开始批次后清零批次数量。
6. 批次操作写入操作日志，便于和报警、配方操作一起追溯。

## 6. M11 细化任务

M11 先完成学习版配方增强闭环：

1. `recipes` 表增加版本、创建时间、更新人和最后下发时间。
2. 新增 `recipe_apply_logs` 表，记录配方下发到 PLC/模拟器的历史。
3. 配方页面增加配方列表和最近下发记录。
4. 保存同名配方时自动递增版本号。
5. 支持从已有配方复制为新配方，便于学习生产中“基于旧工艺微调”的常见流程。
6. 下发配方时记录当前用户、配方版本、目标设备和下发结果。

## 7. M12 细化任务

M12 先完成学习版报警增强闭环：

1. 报警查询支持状态、等级、工位和关键词筛选。
2. 报警表显示确认时间、恢复时间和关闭时间。
3. 选中报警后显示报警详情、确认信息、生命周期时间和处理建议。
4. 报警处理建议先内置在代码中，覆盖当前模拟产线常见报警码。
5. 保持报警确认和恢复的原有生命周期，不改变模拟器联调方式。
6. 后续再扩展时间范围、报警处理备注、批量确认和报表导出。

## 8. M13 细化任务

M13 先完成学习版模拟器增强，让没有真实硬件时也能覆盖更多联调场景：

1. 将离散输入中的传感器、执行机构状态从数字偏移改成命名点位，降低点位表和代码之间的理解成本。
2. 模拟器按运行节拍输出速度扰动，主监控和趋势曲线看到的速度不再是固定值。
3. 灌装量、重量和旋盖扭矩按配方参数生成轻微波动，模拟真实产线采样值。
4. 质量率不再只按固定计数取模，而是按伪随机序列生成合格/不合格结果。
5. 剔除测试命令让下一件产品走一次不良和剔除流程，便于练习不良品处理。
6. 模拟器页面显示传感器、执行机构和质量模拟状态，并增加急停、气压不足、堵瓶、重量不合格、剔除失败、下料满料等故障注入按钮。
7. 暂不做复杂物理仿真，重点仍是帮助上位机练习协议读写、状态判断、报警触发和数据追溯。

## 9. M14 细化任务

M14 先建立真实协议边界，让上位机不再直接调用模拟器对象：

1. 新增 `upkun-simulator.exe` 独立可执行文件，内部启动 `SimulatedModbusServer`。
2. 上位机启动时通过 `QProcess` 拉起独立模拟器进程，再用 `ModbusTcpClient` 连接 `127.0.0.1:1502`。
3. 主监控的启动、停止、复位、批次、配方下发继续走 Modbus TCP。
4. 模拟器页的故障注入改为先写模拟故障码保持寄存器，再写模拟故障线圈。
5. 清除故障改为发送复位命令，不再直接调用模拟器的 `clearAlarm()`。
6. 烟测脚本负责清理上位机启动的模拟器子进程，避免测试后端口残留。
7. 打包脚本同时复制 `upkun-hmi.exe` 和 `upkun-simulator.exe`。

## 10. M15 细化任务

M15 先补通信健壮性和诊断可视化：

1. `ModbusTcpClient` 为每个请求记录发送时间，按 `timeoutMs` 判断超时。
2. 超时请求从挂起队列移除，写命令超时时返回命令失败反馈。
3. 连续超时达到阈值后主动断开连接，进入自动重连流程。
4. 通信层统计请求数、响应数、超时数、错误数、重连次数、挂起请求数和最近往返耗时。
5. 状态栏显示通信质量，便于快速判断当前链路是否稳定。
6. 新增“通信诊断”页，展示端点、质量、请求响应、超时、错误、重连、最近请求/响应时间和最近错误。
7. 暂不做多 PLC 冗余和复杂网络仿真，后续 M16 再补协议回归测试。

## 11. M16 细化任务

M16 先补一条轻量自动化回归链路：

1. CMake 启用 `enable_testing()`，新增 `UpkunRegressionTests` 测试目标。
2. 通过 CTest 注册 `upkun-regression` 测试用例。
3. 测试点位映射，确认线圈、离散输入、输入寄存器和保持寄存器偏移正确。
4. 测试 SQLite 初始化，确认报警、用户、配方、批次和趋势核心表能创建。
5. 测试模拟器 Modbus TCP 协议，确认写入模拟故障码、触发故障和读回报警码闭环可用。
6. 新增 `scripts/regression_test.ps1`，一条命令完成构建和 CTest。
7. 暂不引入 GoogleTest，避免增加额外环境依赖；后续可在此基础上扩展服务层单元测试。

## 12. M17 细化任务

M17 先补部署交付基础能力：

1. CMake 项目版本提升到 `0.17.0`，并通过编译宏传给 HMI 和模拟器。
2. HMI 窗口标题显示版本号，便于截图、测试和发布定位。
3. `AppConfig` 支持读取 `config/app.ini`，不存在时回退到 `config/app.example.ini`。
4. 数据库路径、日志目录、设备地址、端口、轮询周期、超时和重连间隔从配置读取。
5. 启动时初始化 `logs/app-yyyyMMdd.log` 文件日志。
6. 打包目录预创建 `data/` 和 `logs/`，并复制发布检查清单。
7. 暂不做安装向导和自动升级，先保持 portable 发布包。

## 13. M18 细化任务

M18 先扩展一个最贴近当前点位模型的协议方向：Modbus RTU。

1. 新增 `ModbusRtuCodec`，实现 RTU CRC16、CRC 追加和 CRC 校验。
2. 支持生成读保持寄存器、读输入寄存器、写单线圈和写单保持寄存器 RTU 帧。
3. 新增 `ModbusRtuClient`，实现与 `ModbusTcpClient` 相同的 `IDeviceClient` 接口。
4. 配置文件增加 `mode`、`serial_port`、`baud_rate` 和 `slave_id`，默认仍为 `modbus_tcp`。
5. 主窗口根据配置创建 TCP 或 RTU 客户端；RTU 当前提供帧编码和接口骨架，未启用真实串口传输。
6. 回归测试增加 RTU 典型帧 CRC 校验，防止协议编码被破坏。
7. 后续如安装 QtSerialPort，可在 `ModbusRtuClient` 内补真实串口收发，不影响 UI 和业务层接口。

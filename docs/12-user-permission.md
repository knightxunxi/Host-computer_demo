# M9 用户与权限说明

## 1. 本阶段目标

M9 的目标是让上位机从“系统固定操作”进入“可追溯到具体人员”的阶段。当前实现仍是学习版权限，不追求完整账号管理后台，先覆盖真实项目最常见的基础闭环：

- 有用户表。
- 有中文显示名。
- 可在界面快速切换用户。
- 操作日志记录真实用户和角色。
- 关键操作有基础权限判断。

## 2. 用户模型

数据库新增 `users` 表：

| 字段 | 说明 |
| --- | --- |
| `login_name` | 登录名，用于输入和唯一识别 |
| `display_name` | 中文显示名，用于界面和日志展示 |
| `role` | 角色编码：`Operator`、`Engineer`、`Administrator` |
| `enabled` | 是否启用 |
| `password_hash` | 学习版密码哈希 |
| `last_login_at` | 最后登录时间 |

默认用户：

| 角色 | 登录名 | 显示名 | 初始密码 |
| --- | --- | --- | --- |
| 操作员 | `op001` | 张三 | `123456` |
| 工程师 | `eng001` | 李工 | `123456` |
| 管理员 | `admin` | 管理员 | `admin123` |

## 3. 当前权限规则

| 功能 | 操作员 | 工程师 | 管理员 |
| --- | --- | --- | --- |
| 查看主监控 | 允许 | 允许 | 允许 |
| 启动、停止、复位、报警确认 | 允许 | 允许 | 允许 |
| 查看报警和操作日志 | 允许 | 允许 | 允许 |
| 导出趋势 CSV | 允许 | 允许 | 允许 |
| 保存配方 | 拒绝 | 允许 | 允许 |
| 下发配方 | 拒绝 | 允许 | 允许 |

普通操作员默认可以完成现场常规操作；工程师和管理员可以调整会影响生产工艺的配方参数。

## 4. 界面行为

程序启动后会自动登录默认操作员 `op001`。这样做是为了不阻塞自动化烟测和打包验证。

手工测试时，点击顶部状态栏的“切换用户”，选择用户并输入密码即可切换。切换成功后：

- 状态栏显示当前用户和角色。
- 操作日志记录“切换用户”。
- 后续控制、保存配方、下发配方等操作会记录当前用户。

## 5. 后续增强方向

真实项目中用户权限还应继续补齐：

- 强制登录，不再默认自动登录。
- 修改密码和重置密码。
- 登录失败次数限制和账号锁定。
- 权限配置表，而不是在代码里固定角色规则。
- 操作二次确认或电子签名。
- 用户管理界面。
- 密码加盐哈希和更严格的安全策略。

# 企业轻量开发流程

## 1. 流程目标

本项目采用轻量但完整的企业开发流程。目标是在学习 C++ Qt 上位机开发的同时，建立需求、设计、开发、测试、发布和复盘的工程习惯。

## 2. 阶段划分

| 阶段 | 主要活动 | 主要产物 |
| --- | --- | --- |
| 需求分析 | 明确业务场景、用户角色、功能边界和验收标准 | 需求分析文档 |
| 总体设计 | 划分模块、定义数据流、确定技术选型和运行结构 | 总体设计文档、模块清单 |
| 详细设计 | 明确核心类、接口、状态机、数据库表和配置项 | 详细设计文档、接口说明 |
| 开发实现 | 按模块开发、提交代码、保持可运行状态 | 源码、单元测试、提交记录 |
| 联调测试 | 使用模拟器或真实设备验证通信、控制和异常场景 | 测试记录、缺陷清单 |
| 发布部署 | 打包程序、准备运行配置、验证目标机器运行 | 发布包、部署说明 |
| 项目复盘 | 总结问题、经验、技术债和下一轮改进项 | 复盘文档 |

## 3. 文档约定

- 文档使用 Markdown，统一放在 `docs/` 目录。
- 文档先保证可执行和可维护，再追求格式完整。
- 需求变化需要同步更新需求文档和路线图。
- 重要技术决策需要记录原因、替代方案和取舍。

## 4. Git 工作方式

- 默认分支：`main`。
- 学习阶段可以直接在 `main` 上小步提交；进入复杂功能后建议使用功能分支。
- 提交信息建议：
  - `docs:` 文档。
  - `feat:` 新功能。
  - `fix:` 修复。
  - `test:` 测试。
  - `refactor:` 重构。
  - `chore:` 工程配置。
- 每次提交应尽量对应一个清晰目标，避免把文档、重构和功能混在一起。

## 5. 开发节奏

1. 先写或更新需求。
2. 再补充设计和任务拆分。
3. 开发最小可运行版本。
4. 先用模拟协议链路完成通信验证，再接入界面和业务逻辑。
5. 对关键逻辑补测试。
6. 用模拟器完成基本联调。
7. 更新文档并提交。

## 6. 协议模拟学习策略

没有真实 PLC 或现场设备时，通信能力通过模拟方式逐步学习。模拟链路作为正式开发流程的一部分，不只是临时调试工具。

| 阶段 | 学习内容 | 模拟方式 | 目标 |
| --- | --- | --- | --- |
| P1 | TCP Socket | 本机 TCP Server/Client | 理解连接、收发、心跳、超时 |
| P2 | Modbus TCP | 内置或第三方 Modbus TCP Server | 学习寄存器、线圈、轮询、写命令 |
| P3 | 串口通信 | 虚拟串口对 | 学习波特率、校验位、收发缓冲 |
| P4 | Modbus RTU | 虚拟串口 + RTU 模拟器 | 学习从站地址、CRC、串口超时 |
| P5 | OPC UA | 本机 OPC UA Server | 学习节点浏览、读写、订阅 |
| P6 | Snap7/S7 | Snap7 Server 或 S7 模拟环境 | 学习 DB 块、字节偏移、位操作 |

项目实现时优先让上位机通过统一通信接口访问数据源。这样同一套界面和业务逻辑可以先连接模拟器，后续再替换为真实 PLC 或真实协议服务。

## 7. 测试策略

| 类型 | 用途 | 示例 |
| --- | --- | --- |
| 单元测试 | 验证纯逻辑和数据处理 | 报警状态转换、点位解析、配方校验 |
| 集成测试 | 验证模块协作 | 模拟器与通信模块联调 |
| 手工测试 | 验证界面和现场操作流程 | 启动、停止、报警确认、配方切换 |
| 回归测试 | 确认修改未破坏已有功能 | 每个里程碑结束前执行 |

## 8. 缺陷处理

缺陷记录应包含复现步骤、期望结果、实际结果、影响范围、修复方案和验证结果。高优先级缺陷包括程序崩溃、数据丢失、控制命令错误、报警漏报和权限绕过。

## 9. 发布与部署

后续进入可运行阶段后，每个发布版本应包含：

- 程序包。
- 默认配置。
- 数据库初始化脚本或自动初始化逻辑。
- 版本说明。
- 部署和回滚说明。

Windows 环境优先使用 `windeployqt` 收集 Qt 运行库，并使用 Inno Setup 制作安装包。

## 10. 复盘内容

每个阶段结束后记录：

- 已完成内容。
- 未完成内容。
- 遇到的问题。
- 技术取舍是否合理。
- 下一阶段风险和改进项。

# M13 模拟器增强说明

## 1. 阶段目标

M13 的目标是让学习版模拟器更接近真实联调环境。没有真实 PLC 和产线时，上位机仍然可以练习以下能力：

- 周期采样和状态缓存。
- 传感器、执行机构和过程量的综合判断。
- 故障注入、报警触发和恢复。
- 配方参数对生产过程数据的影响。
- 不良品产生、检测和剔除流程。

本阶段不做复杂物理仿真，也不拆分独立模拟器进程。独立进程会放到 M14。

## 2. 核心变化

### 2.1 命名化点位

原先模拟器内部有一部分离散输入直接使用数字偏移，例如 `10`、`20`、`80`。M13 将这些点位补充到 `ModbusPointMap.h`：

- 公共联锁：急停、安全门、气压、电源、PLC 就绪。
- 到位传感器：灌装位、旋盖位、贴标位、下料位。
- 执行机构：输送、灌装阀、理盖机、标签机、剔除气缸。
- 质量检测：重量 OK、重量 NG、剔除确认。
- 下料状态：下料通畅、下料满料。

这样做的目的不是让点位表一次到位，而是让上位机开发者理解“点位表是业务语义和协议地址之间的映射层”。

### 2.2 速度和过程量扰动

模拟器每个周期会基于配方参数生成轻微扰动：

- 当前速度 = 目标速度 + 小范围扰动。
- 实际灌装量 = 配方灌装量 + 小范围扰动。
- 实际重量 = 配方重量上下限内的采样值，或者不良品时超出上下限。
- 实际扭矩 = 配方旋盖扭矩 + 小范围扰动。
- 温度和气压也会有小范围变化。

这些波动用于训练趋势曲线、报警判断和生产记录，不代表真实设备控制算法。

### 2.3 随机不良和剔除测试

质量率仍然来自配方中的模拟质量率，但 M13 不再按产量取模，而是用伪随机序列决定最近产品是否合格。

主监控或后续测试可以使用“剔除测试”命令，让下一件产品强制走一次不良流程。模拟器页会显示最近产品质量和剔除信号状态。

### 2.4 故障注入

模拟器页新增以下故障按钮：

| 按钮 | 报警码 | 影响 |
| --- | --- | --- |
| 急停 | `1001` | 急停联锁断开，产线停机 |
| 气压不足 | `1003` | 气压联锁断开，产线停机 |
| 触发缺瓶 | `2001` | 上料物料不足 |
| 触发堵瓶 | `2002` | 上料/输送异常 |
| 触发缺盖 | `5001` | 理盖机或落盖轨道异常 |
| 重量不合格 | `6002` | 最近产品重量 NG |
| 触发缺标签 | `7001` | 标签纸不足 |
| 剔除失败 | `8001` | 剔除气缸异常 |
| 下料满料 | `9001` | 下料工位堵塞 |

触发故障后，报警服务会继续沿用 M12 的报警生命周期：触发、确认、清除、关闭。

## 3. 界面变化

模拟器页新增四类状态显示：

- 过程量：速度、灌装量、重量、扭矩。
- 传感器：上料、灌装位、旋盖位、贴标位、下料状态。
- 执行机构：输送、灌装阀、理盖机、标签机、剔除气缸。
- 质量模拟：最近产品是否合格、是否触发剔除信号。

界面仍然保持浅白背景和黑色文字，方便后续测试阶段观察状态变化。

## 4. 验证方式

1. 构建项目：

```powershell
cmake --build build
```

2. 运行烟测：

```powershell
.\scripts\smoke_test.ps1
```

3. 手工验证：

- 启动程序后进入“模拟器”页。
- 点击主监控页“启动”，观察速度和工位状态变化。
- 回到模拟器页，观察过程量和传感器状态刷新。
- 点击“重量不合格”或“下料满料”，确认主监控出现对应报警码。
- 点击“清除模拟故障”，再执行报警确认和复位。

## 5. 后续进入 M14

M13 仍然是进程内模拟器。M14 会把模拟器拆成独立程序，上位机只通过协议连接它。这样才能更清楚地区分：

- 上位机：负责界面、业务、数据和报警。
- 模拟器/PLC：负责点位、状态机和协议响应。
- 协议层：负责读写、超时、重连和诊断。

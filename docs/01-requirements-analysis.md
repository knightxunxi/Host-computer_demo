## 2. 背景与目标

本项目模拟一条小型包装产线。产线由上料、输送、灌装或装盒、称重检测、贴标、分拣和下料等工位组成。上位机作为生产现场的人机交互与数据中心，负责查看设备状态、下发控制命令、管理生产参数、记录生产数据、处理报警和辅助现场运维。

项目的核心目标不是一次性复刻真实工厂系统，而是通过可迭代的学习项目覆盖工业上位机常见能力，并形成接近企业开发流程的文档、代码、测试和发布习惯。

## 3. 项目范围

### 3.1 本阶段范围

- 初始化 Git 仓库。
- 建立 Markdown 文档体系。
- 明确业务场景、用户角色、功能需求、非功能需求和后续路线。
- 不实现业务代码。
- 不创建 CMake/Qt 代码骨架。
- 不连接真实 PLC。
- 不配置远程仓库。

### 3.2 后续系统范围

- 上位机主程序：提供操作界面、数据展示、控制入口和业务管理。
- 内置虚拟包装线/PLC 模拟器：在没有真实设备时提供可控的数据源和状态机。
- 本地数据存储：记录生产数据、报警、操作日志、配方和用户信息。
- 部署包：支持在 Windows 工控机环境安装和运行。

## 4. 用户角色

| 角色 | 主要职责 | 权限边界 |
| --- | --- | --- |
| 操作员 | 日常生产操作、查看状态、处理普通报警 | 启停设备、报警确认、查看生产数据 |
| 工程师 | 调试设备、维护参数、排查故障 | 修改工艺参数、维护配方、查看详细日志 |
| 管理员 | 管理用户、权限和系统配置 | 用户管理、权限分配、系统级配置 |

## 5. 业务流程概览

1. 用户登录上位机。
2. 系统连接虚拟 PLC 或真实 PLC。
3. 操作员选择产品配方并确认生产参数。
4. 操作员执行启动，产线进入自动运行。
5. 上位机周期采集设备状态、产量、报警和关键工艺数据。
6. 发生报警时，上位机提示报警并记录历史。
7. 生产结束后，系统保存批次数据并支持查询和导出。

| 编号 | 模块 | 需求描述 | 优先级 |
| --- | --- | --- | --- |
| FR-001 | 用户登录 | 支持操作员、工程师、管理员登录、退出和快速切换用户 | 高 |
| FR-002 | 设备总览 | 展示产线运行状态、当前模式、连接状态、产量和报警数量 | 高 |
| FR-003 | 实时监控 | 展示各工位状态、传感器状态、执行机构状态和关键过程值 | 高 |
| FR-004 | 基础控制 | 支持启动、停止、复位、报警复位等基础控制命令 | 高 |
| FR-005 | 手动控制 | 支持工程师对虚拟电机、气缸、阀门等对象进行手动测试 | 中 |
| FR-006 | 设备模拟 | 提供内置虚拟包装线/PLC 模拟器，用于无硬件学习和测试 | 高 |
| FR-007 | 协议模拟 | 无真实设备时支持通过模拟方式学习 TCP Socket、Modbus TCP、串口、Modbus RTU、OPC UA 和 Snap7/S7 的基础读写与联调流程 | 高 |
| FR-008 | 报警管理 | 支持报警触发、显示、确认、恢复和历史查询 | 高 |
| FR-009 | 生产记录 | 保存批次、开始结束时间、产量、良品数、不良品数等记录 | 高 |
| FR-010 | 趋势曲线 | 展示速度、温度、压力、称重值等关键数据趋势 | 中 |
| FR-011 | 参数配置 | 支持通信参数、采集周期、报警阈值等系统配置 | 中 |
| FR-012 | 配方管理 | 支持产品配方新增、修改、切换和下发 | 中 |
| FR-013 | 操作日志 | 记录用户登录、控制命令、参数修改和报警确认 | 高 |
| FR-014 | 数据导出 | 支持生产记录、报警记录和操作日志导出为 CSV 或 Excel | 中 |

## 7. 非功能需求

| 编号 | 分类 | 需求描述 |
| --- | --- | --- |
| NFR-001 | 稳定性 | 主程序异常应被记录，普通通信异常不应导致界面崩溃 |
| NFR-002 | 通信可靠性 | 支持超时检测、断线提示和自动重连策略 |
| NFR-003 | 可维护性 | 通信点位、系统参数和权限应避免硬编码到界面逻辑中 |
| NFR-004 | 可追溯性 | 报警、操作和生产数据应能按时间查询 |
| NFR-005 | 易用性 | 主界面应优先展示现场最关心的状态、产量、报警和控制入口 |
| NFR-006 | 部署性 | 目标运行环境优先考虑 Windows 工控机 |
| NFR-007 | 可测试性 | 核心通信解析、状态转换和数据处理逻辑应支持自动化测试 |

## 8. 数据对象初步识别

| 数据对象 | 说明 |
| --- | --- |
| 用户 | 用户 ID、登录账号、中文显示名、角色、启用状态、密码哈希、最近登录时间 |

| 操作日志 | 用户、操作类型、操作内容、操作时间、结果 |

## 9. 约束与假设

- 开发环境优先使用 Windows。
- 技术栈默认采用 C++20、Qt 6.10.2 Widgets、CMake、MinGW 64-bit。
- 第一阶段不接入真实 PLC，后续通过内置模拟器降低学习和测试门槛。
- 后续如接入真实设备，优先从 Modbus TCP 开始；无真实设备时，先通过本机模拟服务端、虚拟串口或第三方模拟器学习协议读写、超时、重连和点位映射。
- 协议学习顺序建议为 TCP Socket、Modbus TCP、串口、Modbus RTU、OPC UA、Snap7/S7。
- 数据库优先使用 SQLite，满足单机学习项目的数据记录和查询需求。
